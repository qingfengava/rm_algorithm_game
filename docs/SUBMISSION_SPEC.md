# C++23 算法提交规范

## 0. 语言限制

选手提交语言仅允许 C++。平台只接受符合本规范的 C++23 源码，不接受 Python、Java、Rust、Go、JavaScript、脚本、预编译可执行文件或其他语言提交。

## 1. 提交内容

提交文件为一个 ZIP 压缩包：

```text
submission.zip
└── bot.cpp
```

`bot.cpp` 必须包含：

```cpp
#include <arena/api.hpp>

extern "C" arena::Player* create_player();
```

选手不需要也不允许提供 `main()`。运行器负责创建 `Player`、驱动回调和销毁对象。

## 2. 编译环境

官方编译环境使用固定的 C++23 工具链：

```bash
g++ -std=c++23 -O2 -pipe -I/opt/arena/sdk/include \
    -I/opt/arena/runner/include \
    /opt/arena/runner/src/main.cpp /opt/arena/runner/src/protocol.cpp \
    /opt/arena/runner/src/seccomp.cpp bot.cpp \
    -o bot_runner
```

可使用的库：

- C++ 标准库。
- 官方 `arena/api.hpp`。

不允许依赖第三方库、系统安装的额外头文件、预编译二进制文件或动态下载的依赖。

## 3. 资源限制

| 项目 | 限制 |
|---|---:|
| ZIP 大小 | 5 MB |
| 编译时间 | 30 秒 |
| 单次 `act()` | 50 ms |
| 单场比赛总运行时间 | 10 秒 |
| 内存 | 256 MB |
| CPU | 1 个逻辑核心 |
| 进程数 | 1 个选手进程 |

超过资源限制时，按照规则判定该算法输掉当前比赛。编译失败的提交不会进入比赛。

## 4. 沙箱限制

选手程序运行在独立沙箱中：

- 无网络访问。
- 不能读取宿主机文件。
- 不能访问其他选手进程。
- 不能创建子进程或线程。
- 不能执行外部程序。
- 不能读取地图种子。
- 不能访问比赛数据库、队列和回放服务。
- 不能依赖系统时间、随机设备或环境变量获取比赛信息。

标准输出和标准错误不属于算法通信接口，平台可以丢弃或限制其输出。算法不应依赖日志输出完成比赛。

## 5. 失败处理

| 情况 | 提交状态或比赛结果 |
|---|---|
| ZIP 格式错误 | 拒绝提交 |
| 缺少 `bot.cpp` | 拒绝提交 |
| 编译错误 | `COMPILE_FAILED` |
| 违反依赖限制 | 拒绝提交 |
| `act()` 超时 | 当前比赛判负 |
| 进程崩溃 | 当前比赛判负 |
| 违反沙箱 | 当前比赛判负 |
| 裁判基础设施故障 | 比赛作废并重新调度 |

非法但可解析的操作会作为一次 `Invalid` 行动处理，消耗一个行动点，不直接判负。

## 6. 提交和对战流程

提交处理顺序：

```text
上传 ZIP
  |
格式检查
  |
编译
  |
沙箱启动测试
  |
基础 bot 资格赛
  |
加入比赛队列
  |
与其他当前有效算法交换红蓝方各比赛一次
  |
更新排行榜
```

每一对算法固定进行两场 BO1：

```text
算法 A 红方，算法 B 蓝方
算法 B 红方，算法 A 蓝方
```

两场比赛使用相同地图。

正式排队前，候选算法必须在固定资格地图上分别担任红方和蓝方，击败平台内置的基础 bot。两场资格赛都获胜才算通过；任意一场失败、平局、超时、崩溃或协议错误都会拒绝提交。资格赛只用于提交门槛，不计入排行榜战绩。

资格赛的基础 bot 行为和固定地图见 [`docs/QUALIFICATION.md`](QUALIFICATION.md)。

同一用户重新提交后，新提交成为该用户当前有效算法。历史提交的比赛记录可以保留，但历史提交不再参与当前排行榜。

## 7. 行为要求

选手程序应满足：

- `create_player()` 返回非空指针。
- `act()` 每次都返回一个合法的 `arena::Action`。
- 不保存指向下一次回调后失效的外部对象。
- 不假设每次行动都能成功。
- 能处理侦查结果为空的情况。
- 能处理移动、升降、开火失败。
- 不依赖对手一定在侦查范围内。

## 8. 提交验收

平台在正式排队前执行：

1. C++23 编译检查。
2. `create_player()` 加载检查。
3. 空地图示例赛。
4. 障碍物地图示例赛。
5. 超时和崩溃隔离测试。
6. 内存和文件访问限制测试。

所有测试通过后，提交才进入正式比赛队列。
