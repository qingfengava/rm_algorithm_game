# 4x4 无人机算法对抗赛规则

本文档是比赛规则的唯一依据。选手提交语言仅允许 C++，统一使用 C++23 选手 API。规则引擎不向选手暴露地图种子、完整地图或对手程序。

## 1. 比赛目标

双方各控制一架无人机，在一个包含上、下两个平面的 4x4 地图中行动。无人机被敌方弹丸命中后立即淘汰，击毁敌机的一方获胜。

每场比赛最多进行 20 个完整回合。20 个回合结束时双方都存活，比赛判定为平局。

## 2. 地图和坐标

地图坐标为 `(x, y, z)`：

- `x` 范围为 `0..3`，从西向东增加。
- `y` 范围为 `0..3`，从北向南增加。
- `z=0` 表示下平面。
- `z=1` 表示上平面。

平面中的一个格由 `(x, y)` 表示，完整地图格由 `(x, y, z)` 表示。每个完整地图格最多存在一个障碍物和一架无人机。

双方初始状态固定为：

| 阵营 | 位置 | 平面 | 初始朝向 |
|---|---|---|---|
| 红方 | `(0, 0, 0)` | 下平面 | 东 |
| 蓝方 | `(3, 3, 0)` | 下平面 | 西 |

红方和蓝方可以在相同的 `(x,y)` 上处于不同平面，但不能在同一平面的同一格重叠。

## 3. 障碍物生成

每张地图恰好生成 4 个障碍物。障碍物属于具体的 `(x,y,z)` 格，两个平面可以在相同 `(x,y)` 位置分别拥有障碍物。

出生点下平面的 2x2 安全区不参与抽样。安全区定义为：红方 `x=0..1,y=0..1`，蓝方 `x=2..3,y=2..3`。

```text
(0,0) 到 (1,1)  红方出生点附近的下平面 2x2 区域
(2,2) 到 (3,3)  蓝方出生点附近的下平面 2x2 区域
```

其余 24 个格按照 `(z, y, x)` 的升序排列后，使用给定的 64 位 `map_seed` 进行无放回抽样。参考实现使用 `std::mt19937_64` 做前向 Fisher-Yates 抽样：对 `i=0..3` 计算 `j = i + rng() % (24 - i)`，交换第 `i` 和第 `j` 个元素，最终取前 4 个元素。地图种子由裁判服务生成，选手不能读取。

因此，出生点对应的上平面格可以生成障碍物；如果该格有障碍物，出生在下平面的无人机第一次升降会失败。安全区只限制下平面障碍物。

障碍物具有以下效果：

- 无人机不能进入障碍物格。
- 弹丸遇到障碍物后立即停止，障碍物不会被摧毁。
- 升降的目标平面格有障碍物时，升降失败。
- 侦查不被障碍物阻挡，可以看到侦查范围内的障碍物和敌机。

## 4. 回合和行动顺序

比赛由第 1 到第 20 个完整回合组成。每个完整回合固定按照以下顺序执行：

```text
红方行动 1
红方行动 2
红方行动 3
蓝方行动 1
蓝方行动 2
蓝方行动 3
```

每次行动提交后立即结算并更新状态。红方在每个完整回合都先行动，不进行先手轮换。

如果红方或蓝方在某次行动中被击毁，比赛立即结束，后续行动不再执行。

## 5. 行动定义

### 5.1 移动

移动操作带有一个绝对方向：北、东、南、西。无人机向该方向移动一格，并保持原朝向。

目标格满足以下任一条件时，移动失败：

- 超出地图边界。
- 目标格存在障碍物。
- 目标格已有敌方无人机。

移动失败不改变无人机状态，但仍消耗一次行动。

### 5.2 转向

转向操作将无人机朝向直接设置为指定的绝对方向。即使目标方向与当前方向相同，也消耗一次行动。

转向不会改变位置和平面。

### 5.3 升降

升降操作将无人机从当前平面切换到另一平面，位置 `(x,y)` 不变。

以下任一条件成立时升降失败：

- 目标平面对应格存在障碍物。
- 目标平面对应格已有敌方无人机。

升降失败不改变平面，但仍消耗一次行动。

### 5.4 开火

开火沿无人机当前朝向发射一枚弹丸。弹丸最多检查前方第 1、2、3 格，并且只在当前平面飞行。

弹丸按以下顺序处理：

1. 飞出地图边界，弹丸消失。
2. 遇到障碍物，弹丸停止。
3. 遇到敌方无人机，敌方立即被击毁，比赛结束。
4. 检查完 3 格仍未命中，开火判定为未命中。

如果障碍物位于敌机之前，弹丸不能穿过障碍物命中敌机。

### 5.5 侦查

侦查以无人机当前格为中心，查看当前平面的 3x3 区域。区域由相对偏移 `dx=-1..1`、`dy=-1..1` 定义。返回数组按照 `dy` 从 `-1` 到 `1`、每个 `dy` 内 `dx` 从 `-1` 到 `1` 的顺序排列。

每个区域格返回：

- 是否位于地图内。
- 绝对坐标（越界格为 `-1`）。
- 是否存在障碍物。
- 是否存在敌方无人机。

侦查不会查看另一平面，也不会返回地图边界之外的信息。

## 6. 选手可获得的信息

比赛开始时，选手获得：

- 自身阵营。
- 地图尺寸。
- 自身出生位置、平面和朝向。
- 最大回合数和每回合行动数。

每次轮到选手行动时，选手获得：

- 当前回合编号。
- 当前是本回合的第几次行动。
- 自身位置、平面、朝向和存活状态。
- 自己上一次行动的结果。
- 如果上一次行动是侦查，则获得本次侦查结果。

选手不会被动获得敌机位置、完整障碍物地图或敌方上一行动内容。选手需要自行保存已经侦查到的信息。

比赛结束后，不再调用选手 API。

## 7. 非法操作和运行故障

以下情况属于非法操作：

- 操作类型不是 API 定义的五种类型之一。
- 操作参数格式损坏。
- 方向字段无法解析。

非法操作的处理方式是：不改变地图状态，记录 `INVALID`，消耗一次行动。

以下情况直接判定当前算法输掉本场比赛：

- `act()` 超过规定时间没有返回。
- 算法进程崩溃或被系统终止。
- 算法进程违反沙箱限制。

如果规则引擎、比赛 Worker 或基础设施故障，比赛标记为平台故障，不计入双方战绩，并由调度器重新执行。

## 8. 胜负和平局

结果优先级如下：

1. 某方无人机被击毁，另一方获胜。
2. 某方算法发生超时、崩溃或沙箱违规，对方获胜。
3. 第 20 回合蓝方第 3 次行动结束后双方都存活，判定平局。

由于行动是顺序结算，不存在同一行动同时击毁双方的情况。

## 9. 排行榜对局规则

对于每一对算法，固定进行两场 BO1：

```text
比赛 A：算法 1 为红方，算法 2 为蓝方
比赛 B：算法 2 为红方，算法 1 为蓝方
```

两场比赛使用同一张地图，以排除红蓝出生位置和先手顺序带来的固定偏差。

同一用户重新提交后，新提交替换该用户当前有效算法。旧提交的比赛记录和回放可以保留，但不再参与当前排行榜。

每个算法的统计字段为：

```text
N = W + L + D
胜率 = W / N
得分率 = (W + 0.5 * D) / N
```

排行榜排序顺序：

1. 得分率降序。
2. 总得分降序。
3. 胜场数降序。
4. 相互对战得分率降序。
5. 异常退出次数升序。
6. 首次提交时间升序。

没有完成任何比赛的算法显示为“未定级”。

## 10. 边界情况

| 情况 | 处理 |
|---|---|
| 移动到边界外 | 移动失败，消耗行动 |
| 移动到障碍物 | 移动失败，消耗行动 |
| 移动到敌机所在格 | 移动失败，消耗行动 |
| 升降目标格有障碍物 | 升降失败，消耗行动 |
| 升降目标格有敌机 | 升降失败，消耗行动 |
| 转向到当前方向 | 转向成功，消耗行动 |
| 弹丸飞出边界 | 开火未命中 |
| 弹丸遇到障碍物 | 弹丸停止，开火被阻挡 |
| 侦查触及边界 | 越界格返回 `in_bounds=false` |
| 第 20 回合结束双方存活 | 平局 |
| `act()` 超时 | 当前算法判负 |
| 算法崩溃 | 当前算法判负 |
| 规则引擎故障 | 比赛作废并重新调度 |
